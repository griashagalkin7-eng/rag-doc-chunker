# rag-doc-chunker

Небольшой Python-инструмент для подготовки документов к RAG: извлекает текст, делит его на чанки и сохраняет Markdown с метаданными.

Поддерживает TXT, Markdown, PDF с текстовым слоем, DOCX (абзацы и таблицы), HTML. Обрабатывает вложенные папки.

## Запуск

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdir -p input_docs
# Положите документы в input_docs
python chunker.py
```

В Windows активируйте окружение командой `.venv\Scripts\activate`.

Результат появится в `output_md_chunks/`. Можно указать свои папки:

```bash
python chunker.py --input ./documents --output ./chunks
```

## Настройки и результат

В начале `chunker.py`:

- `CHUNK_SIZE = 1800` — максимальный размер текста чанка в символах, включая overlap и разделитель; Markdown-обёртка не учитывается.
- `CHUNK_OVERLAP = 250` — максимальный размер контекста из предыдущего чанка. Фактическое пересечение может быть меньше.
- `MIN_CHUNK_SIZE = 300` — желаемый минимум: небольшие чанки объединяются, когда позволяет лимит.

Каждый исходный документ получает отдельный Markdown-файл. Метаданные чанка содержат ID, относительный путь источника, номер, общее число чанков и длину текста. Имя выходного файла включает расширение источника и хеш пути. ID зависит от пути, номера и полного текста чанка.

## Ограничения

Это эвристический чанкинг по абзацам и предложениям, без embeddings и семантической модели. Размер считается в символах, а не токенах. Сканы PDF требуют отдельного OCR. Сложная вёрстка PDF, вложенные таблицы DOCX и структура Markdown могут передаваться неточно; длинные блоки кода могут разделяться. Отступы сохраняются, но границы Markdown-блоков не анализируются. Для HTML удаляются script, style, nav, footer и header. TXT, MD и HTML должны быть в UTF-8; ошибки чтения выводятся в отчёте.

Markdown — промежуточный экспорт: при индексации отделяйте текст чанка от служебной обёртки. Качество поиска нужно проверять на своих документах и embedding-модели. OCR, векторная база и поиск в проект не входят.

## Проверка

```bash
python -m unittest discover -s tests -v
```

При ошибке обработки хотя бы одного документа программа возвращает код 1 и продолжает обработку остальных файлов.
